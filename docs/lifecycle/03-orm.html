Durability

Six commit boundaries

Green is Postgres, violet is Redis, hatched amber is a window where the connection is held but nothing is written. There is no distributed transaction, no outbox, and no 2PC — the design answers that by making Postgres authoritative and Redis advisory, then reconciling with a reaper.

Transaction GanttTX-2 holds a pooled connection for 30–90 s
The idle windowTX-2

blog_worker.py:84 opens a session, then :86 runs the entire ADK pipeline — five to ten Gemini calls plus a Tavily round trip. The connection sits idle the whole time.

  • pool_size=10, max_overflow=20 · pool_pre_ping=True
  • Semaphore(3) × 2 replicas = 6 concurrent jobs → 6 idle connections
  • No READ COMMITTED blocking today, because no other transaction touches those rows while the lease is held
  • But a third concurrent phase for the same session would block on the same rows for the full duration
Redis is outside every commitordering
  • LPUSH before COMMIT — a worker can dequeue before the row is visible; it then blocks on SELECT … FOR UPDATE
  • If TX-A fails, the job is orphaned in Redis. The worker's lease acquire returns false, the job is acked and dropped — silently
  • The reaper cannot rescue it: get_queued_without_active_leases needs a row to exist
  • ZREM ack correctly follows the commit (blog_worker.py:87→88)
  • Lease release runs in a fourth transaction, after the ack
