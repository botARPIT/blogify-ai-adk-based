The three buckets

Survives intact

Reaches a consumer that actually uses it.

  • topic → outline agent → draft
  • audience → outline agent
  • blog_outline → research agent
  • research_data → editor agent
  • blog_draft → editor agent
  • editor_review → final_content
  • adk_session_id → Redis session key
  • invocation_id + confirmation_request_id → ADK resume
  • BlogJob.phase → executor dispatch
Written, never read

Persisted correctly, but no code path consumes it. Deleting the column would change no behaviour.

  • intent_result — no column, snapshot only
  • approved_outline — no agent interpolates it
  • outline_feedback — never reaches the LLM (F-09)
  • outline_review_result — wiped on revision (F-10)
  • tone — stored, echoed, never applied (F-04)
  • editor_review.sources_section — not persisted
  • CostInfo.research_sources — always []
  • agent_runs.latency_ms / completed_at — always NULL (F-08)
  • failure_reason — overwritten by rejection text
Lost in transit

Created, persisted, then destroyed — or never recorded at all.

  • Pre-approval outline — overwritten twice (F-06)
  • outline_review_agent tokens — unmetered (F-03)
  • All revision spend — skipped by cost recorder (F-05)
  • Account reserved_usd on revision — no open reservation (F-05)
  • Full ADK event stream — dropped after cost extraction
  • Reservation on abandoned outline review — never released (F-15)
  • Topic validity flag — discarded by tuple unpack (F-01)
The pattern. Nothing here is a race condition or a distributed-systems problem. Every break is a silent drop at a boundary — a tuple unpack that discards a validity flag, a dict lookup that misses an author name, a guard that checks status == COMPLETED and concludes "already recorded" when it means "already billed once, but this is a new run".
